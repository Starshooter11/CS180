Part A: Exploring the Power of Flow Models

Flow-based generative models or Flow models are a generative model used in ML that models a probability distribution by leveraging normalizing flow. Normalizing flows essentially takes in a simple base distribution , Gaussian for example, and transforms it into a target complex distribution using a sequence of invertible transformations. This lets the model learn the probability density of the data.

In this (part of the) project, I will be using PixNerd, a pre-trained text-to-image model. This model can't take in raw text, so I will also be usingQwen3 to encode the text into prompt embeddings.

Part 1: Visualizing Training and Sampling

For the optimal-transport(OT) formulation of flow matching, I will use linear interpolation. Let $x_0 \sim N(0,1)$ and $x_1$ be a clean image. Then

$$x_t = (1-t)x_0 + tx_1, \quad t \in [0,1].$$

Notice that $t=0$ is pure noise and $t=1$ is the clean image.

As for generating the training datast, I sample the clean image $x_1$, independent Gaussian noise $x_0$ and $t \sim U[0,1]$. The model recieves $(x_t, t, c)$ using the above linear interpolation and c is a condition. The model is trained to predict the path velocity of $x_1 - x_0$. This makes the loss:

$$L(\theta) = \mathbb{E}[||v_{\theta}(x_t,t,c) - (x_1-x_0)||_2^2]$$

To refrain from the model's learning becoming temporal, we evaluate based on randomly selected times.

Although each training pair defines a straight path, learned sampling trajectories are generally curved since the predicted direction will change with the current image and time. To account for this, I will integrate the velocity field numerically, using Euler steps that recompute the velocity after each update.

Part 1.2: Classical denoising

If you may remember from a previous project(hint hint 2), I used a Gaussian blur to denoise a picture before applying convolutions. So lets use that as the baseline!

As it turns out, averaging nearby pixels partially cancels independent, zero-mean noise. However, this does mean that stronger blur reduces noise but also removes image detail. Reminder that the other project's low-pass which displayed low-frequency parts of an image was the Gaussian blurred version of said image! Image detail, which is basically the high-pass or high-frequency parts, is what you get from subtracting the Gaussian blur from the original image. But...we aren't given the original image. Hence, this classical denoising using a Gaussian blur really isn't that great.

The equation used is as follows:

$$\frac{x_t}{t}=x_1 + \frac{1-t}{t}\epsilon, \quad \hat{x}_1^{\text{blur}} = G_{\sigma}(\frac{x_t}{t})$$

Where $G_{\sigma}$ is a Gaussian filter with standard deviation $\sigma$. I divide by t to correct the image amplitude.

Part 1.3: One-step Denoising

Now, lets use the PixNerd model! It comes with a predict_velocity(x,t,c) function that predicts the velocity at the noisy image and time. I then extrapolate to the clean endpoint using one prediction:

$$\hat{x}_1 = x_t + (1-t)v_{\theta}(x_t,t,c)$$

Since this model is trained with text conditioning, I use the embedding for "a high quality photo".

Already looking a lot cleaner. Even though the .25 and 50 are a still blurry compared to the original photo, you can't see any remnants of the Gaussian noise, unlike the outputs from classical denoising.

Part 1.5: Iterative Denoising with Euler Sampling

Obviously, one-step isn't perfect. This is due to the learned velocity changing as we move along the path. Instead, take a small step, predict a new velocity, and repeat. Using Euler integration:

$$x_{t+h}=x_t+hv_{\theta}(x_t,t,c)$$

For this portion, I will use $h=0.02$.

Part 3.3: Visual Anagrams

Let's try another image editing: visual anagrams! Images that look like one thing in one direction, and something else in another direction. The velocity algorthim for this is:

$$v_1= \text{CFG velocity}(x_t, t, p_1)$$ $$v_2 =\text{flip}(\text{CFG velcotiy}(\text{flip}(x_t),t,p_2))$$ $$v = \frac{v_1+v_2}/2$$

Part 3.4: Hybrid Images

Now, let's create hybrid images! Similar to the technique used in 3.3, for this one we create an image that, when viewed up close and viewed faraway, look different. Essentially, we'll predict the velocity with two different text prompts, and then combine the low frequencies from one velocity estimate with the high frequencies of the other.

$$v_1 = \text{CFG velocity}(x_t, t, p_1)$$ $$v_2 = \text{CFG velocity}(x_t, t, p_2)$$ $$v = f_{\text{lowpass}}(v_1) + f_{\text{highpass}}(v_2)$$

Part 2: Training a Flow Matching Model

This one-step doesn't work well for generative tasks. Instead, we should iteratively denoise the image. So lets do that with flow matching. We will iteratively denoise an image by training a UNet model to predict the `flow' from our noisy data to clean data. In our flow matching setup, we sample a pure noise image and generate a realistic image. Intermediate noisy samples are constructed via linear interpolation between noisy and clean.
